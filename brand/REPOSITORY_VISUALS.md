# Project identity and repository visual system

Status: **M4 complete and approved; M5 complete and approved**. M1–M5 are approved. These are fictional specimen cards, not a rollout to existing repositories.

## Lightweight project identity generator

Patitos Fortune supplies the fixed visual grammar; each project supplies controlled content. The result is an immediately recognizable project-level identity for an experiment within the laboratory, not an independent sub-brand. The 1280 × 640 GitHub social preview is one application of that identity. The same name, category, descriptor, single accent and study motif can inform a future project header, documentation cover or website project entry without inventing another logo system. Those additional formats are not generated by the current tooling.

For a future rollout, gather the required name/descriptor and choose a relevant study motif; optionally supply category and a meaningful catalogue ID, then select one canonical accent and Paper/Ink field. Generate into a separate directory, render and inspect, and seek project-specific approval before publication. Keep `sample: true` while using fictional content. Do not treat approval of the system or a manifest status as automatic approval of future project content. No existing repository identity has been created during M5.

## Composition and family resemblance

The project leads; the laboratory signs the work. A double-rule specimen label, editorial title, separate study field and small colorful duck attribution connect distinct projects to Patitos Fortune. Each card has one illustration and one project accent. The duck retains the full approved facet palette independent of that accent.

| Fixed | Controlled by the project |
| --- | --- |
| 1280 × 640 canvas; 64 px essential-content margin | Project title and short descriptor |
| Double frame at 24/32 px; divider at x824; footer rule at y492 | Paper or Ink background |
| Serif title, sans descriptor, mono catalogue labels | One accent: Ochre, Rust, Sage or Mist |
| Title/descriptor column ending before x792 | Optional category and catalogue identifier |
| Study region x864–1216, y144–480 | A relevant built-in diagram, or an empty study field |
| 80 px duck artboard and lab attribution in the footer | Explicit title line breaks where useful |

The outer rules are decorative and intentionally outside the safe margin. Essential text and the full duck artboard stay inside it. The title starts at x68 to accommodate serif overhang; the descriptor starts at x66. Use a solid field rather than transparent text over an unknown website background.

### Brand marks

Paper cards copy the exact primary Geometric Impossible Duck. Ink cards copy the approved M2 Ink avatar, including its light facet substitutions. This preserves the primary colorful expression on both fields. The project accent never recolors the duck. The lab signature remains smaller than the project name.

Technical PA, PF, round/rectangular stamps and their aged/construction derivatives remain complementary assets. Reserve them for a relevant research figure, institutional note or large documentation colophon; they are not extra badges on every preview. Do not combine several lab marks on one card or turn a diagram into a competing repository sub-brand.

## Structured input contract

Use UTF-8 JSON with `schemaVersion: 1` and a `cards` array. Unknown card fields are rejected. No image URLs, external SVG imports or remote fonts are loaded.

| Field | Contract |
| --- | --- |
| `id` | Required unique lowercase kebab-case filename stem; letters and digits; `social-preview-template` is reserved |
| `name` | Required nonblank string, at most 84 characters; short editorial name preferred; `\n` requests a line break |
| `descriptor` | Required nonblank string, at most 140 characters; concise sentence; `\n` allowed |
| `category` | Optional single-line string, at most 24 characters; omitted field becomes `REPOSITORY`; empty string hides it |
| `catalogueId` | Optional single-line string, at most 16 characters; omit unless the project has a meaningful identifier |
| `accent` | `ochre` (default), `rust`, `sage`, `mist`; canonical palette tokens only |
| `theme` | `paper` (default) or `ink` |
| `motif` | `number-grid`, `route`, `data-bars`, `oscillation`, or `none` (default, empty study field) |
| `sample` | Boolean, default false; true adds a visible fictional-sample label and accessible description |

```json
{
  "schemaVersion": 1,
  "cards": [{
    "id": "fictional-number-study",
    "name": "Number\nStudy",
    "descriptor": "Explore patterns and satisfying solutions.",
    "category": "Puzzles",
    "accent": "ochre",
    "theme": "paper",
    "motif": "number-grid",
    "sample": true
  }]
}
```

Character limits are upper bounds, not a promise that every string fits. The generator wraps on spaces, hyphens and slashes, then breaks exceptionally long tokens. Title sizes step through 80/72/64/56/48/44 px, at most three lines; three-line titles use at most 56 px. Descriptors use 25/24 px and at most three lines. Unrenderable input fails before any output is written. Prefer a readable display title to an excessively long repository slug. Never shrink indefinitely or clip text.

The width estimate is conservative but font metrics differ. Browser validation is mandatory for each new card. It measures real text bounds with preferred and generic fallback fonts, separation from the descriptor, the illustration region and the essential-content margin. Unusual scripts, emoji, custom fonts and new illustrations require separate rendering review.

The current contract deliberately offers four local diagram presets rather than arbitrary asset ingestion. A future project icon can occupy the same study field through a reviewed extension to `motif()` in the generator. Preserve its aspect ratio, safe bounds, one-accent discipline and accessible description. Such an extension is not implemented in M4.

## Generate and verify

Run from the repository root with normal Python (assertions enabled):

```text
python brand/tools/build-social.py
node brand/tools/render-social.cjs "<review-directory>" "<Chromium-executable>"
python brand/tools/validate-social.py --renders "<review-directory>"
```

For separate project inputs and outputs, without replacing the reviewed examples:

```text
python brand/tools/build-social.py --input "<input.json>" --output-dir "<card-directory>"
node brand/tools/render-social.cjs "<review-directory>" "<Chromium-executable>" "<card-directory>"
python brand/tools/validate-social.py --source-dir "<card-directory>" --renders "<review-directory>"
```

Generation and structural validation use Python's standard library. Rendering uses the existing Node/Playwright runtime and a Chromium-compatible browser; no new dependencies or font files were installed. SVG and manifest generation is byte-deterministic for the same inputs and source assets. PNGs depend on the selected browser and installed fonts; preserve the renderer report with each export. Reports include source and PNG hashes to detect stale evidence.

Text stays editable with the established serif/sans/mono fallback stacks. Generic fallback rendering passes without requiring a particular proprietary font. Exact cross-platform typography is not promised; the exported PNG fixes the reviewed appearance for upload.

GitHub documents a recommended **1280 × 640** social image, a minimum **640 × 320**, accepted PNG/JPG/GIF formats and a file size **under 1 MB**. These exports are opaque PNGs with Paper or Ink backgrounds and remain well below that limit. [GitHub social-preview documentation](https://docs.github.com/en/enterprise-cloud%40latest/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview)

No images have been uploaded. Actual link-unfurl cropping and compression on GitHub or other services remain unverified. The safe margin is this system's design rule, not a guarantee about every third-party crop.

## Application inside repository READMEs

Keep the repository's native heading, purpose, installation and usage easy to find. A plain-text “A Patitos Fortune project” link to the organization is usually sufficient parent attribution. If a mark helps, use one small approved colorful duck on its explicit Paper field, with useful alt text or empty alt text when it only repeats adjacent text. Do not use the unchanged dark facets directly on a dark page.

An optional shallow project header may use this typography, accent and attribution hierarchy. Do not automatically paste the entire 1280 × 640 social card into a README. Skip large branding when it delays the first useful instructions, repeats the page title or compresses important text on phones. No slim-header asset is added by M4.

The project remains the named subject; Patitos Fortune is its parent lab. Use the project name and purpose as real Markdown even when they appear in an image. Provide descriptive image alt text and never encode necessary instructions only as diagram colors. Copy only the required approved image into that project's own documentation assets and use a local relative path; paths into this `.github` checkout will not resolve inside another repository.

Use an explicit Paper/Ink field or a deliberately reviewed theme-specific asset. Test narrow screens and light/dark modes. Fine stamp lettering, PA discovery and construction guides belong at useful large sizes; they are unsuitable replacements for navigation, status or tiny functional icons. Preserve pristine Paper in aged stamp derivatives.

M4 supplies guidance only. No other repository has been modified. M5 consolidates the approved system; project rollout and uploads require later authorization. Commit, branch push and PR publication are now authorized; merge and deployment remain separate.

## Anti-patterns

Avoid inventing project palettes, changing duck facets to match an accent, making the lab signature larger than the project, stacking stamps and monograms, inventing meaningless study IDs, or using decorative plots to imply measured findings. Illustrations should explain the project subject; data shown in samples is illustrative. Keep important meaning in text, and avoid long raw slugs or tiny descriptors that must be read at thumbnail size. Projects remain Patitos Fortune experiments rather than separate brands.
